Unnovate Brains — Document Builder

Documentation: a driver-based, contract-first document execution framework (PDF, Word, Excel, CSV) designed to be Laravel-friendly while remaining framework-agnostic.

Overview

This package lets applications define documents as execution plans and delegates all processing to a pipeline that loads data, renders templates, executes format-specific engines and stores the result. The core is driven by contracts and drivers so the package can be extended without coupling it to specific application code or storage backends.

Installation

Install via Composer:

composer require unnovatebrains/document-builder

If the package provides a Laravel service provider, register it (or rely on package auto-discovery). Publish configuration and other assets when available.

Quick start

Example usage demonstrates the public API vision. Adapt the code to the concrete classes and facades provided by the package implementation.

// Create and queue a PDF from a collection
Document::pdf()
    ->fromCollection($students)
    ->view('reports.students')
    ->engine('mpdf')
    ->chunk(100)
    ->merge(true)
    ->queue()
    ->dispatch();

// Save a Word document
Document::word()
    ->fromModel($invoice)
    ->view('documents.invoice')
    ->save();

// Generate an Excel file
Document::excel()
    ->fromQuery(Student::query())
    ->save();

// Generate a CSV
Document::csv()
    ->fromCollection($students)
    ->save();

Core concepts

  • Builder — collects options (type, engine, data source, view, storage, processing options) and creates an execution plan.
  • Execution Plan — immutable, serializable definition of how to build the document.
  • Pipeline — orchestrates execution: resolve context, load data, transform, render, run engine, store result.
  • Driver — format-specific renderer (e.g., mPDF driver for PDF).
  • Storage — abstracted by contracts so implementations can be local disk, S3, MinIO, etc.
  • Queue — package defines queue contract; integration with worker systems is pluggable.

Drivers and rendering engines

Drivers isolate format-specific rendering. Typical engines:

  • PDF: mPDF, Chrome PDF (headless), TCPDF
  • Word: PHPWord
  • Excel: PhpSpreadsheet
  • CSV: native CSV writer

To add a new engine, implement the driver contract and register the driver with the registry provided by the core.

Storage

The package defines a storage contract. Implementations are responsible for:

  • temporary files
  • generated documents
  • chunks and merged files

Applications can provide host services that map storage paths to tenant/school contexts, for example:

tenants/{tenant}/schools/{school}/documents

Queue execution

Queue-based execution is optional. The package defines a queue contract and integrates with queue backends through adapters. Example queue backends: Laravel Queue, Redis, SQS, database queue.

Extending the package

Recommended extension points:

  • Drivers — implement new drivers for additional formats or engines.
  • Storage adapters — implement storage contract to support target storage systems.
  • Context hosts — supply tenant, school, or user context for multi-tenant applications.

Design rule: keep the core independent and rely on contracts — do not include application-specific logic in the core.
